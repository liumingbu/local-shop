# 原生小程序开发与验收边界

## 当前代码

原生TypeScript/WXML/WXSS，顾客入口、指定店铺、商品多图、询货/需求草稿、本人记录、处理详情、开发隐私说明共7页。商户手机页在后续模块实施，实际进度见PROGRESS。

一个AppID承载多店，store_id明确定位。无效/暂停店铺不会自动跳到其他店。商品参考价不计算应付，没有支付入口或假库存。
草稿和未知结果请求按认证用户+店铺+类型隔离；不同单位/规格不合并。未登录只能浏览，登录后才登记。图片上传/记录提交分开，不把“上传成功”写成“需求已提交”。

## 构建

```sh
npm ci
npm run typecheck
npm run build -w apps/miniprogram
npm run test:native
```

构建先清理生成目录dist，再编译TS并复制app.json声明的原生资源。项目根`apps/miniprogram/project.config.json`指向`dist/`；touristappid只是占位。类型和资源检查不等于WXML经过微信编译器或页面渲染通过。

`config.ts`默认apiOrigin为空、enableDevelopmentLogin=false。进入配置缺失页面显示明确阻塞，不默默使用另一个服务器。
受控模拟必须同时满足：显式开关、开发版envVersion=develop、API为localhost/127.0.0.1；后端仍要求回环访问、非生产和DEV_AUTH_ENABLED。trial/release禁止模拟登录。正式HTTP明文地址拒绝；生产要求单独验证HTTPS域名和真实身份适配，不沿用旧佳琪配置。

## 自动测试的真实范围

1. `npm run test:native`：Node中执行实际编译后的TS逻辑，wx对象、页面生命周期/存储/选择图片由测试桩模拟。覆盖身份切换、陈旧响应、按店草稿、重复点击、未知网络结果同键重试、页面离开后结果、取消选择、参数/存储失败等。
2. 下列脚本在Dot同一云电脑启动真实PostgreSQL16.15、API与Web，编译原生代码，再用模拟wx网络适配器调用真实HTTP接口：

```sh
PG_BIN=/path/to/postgresql-16.15/bin .venv/bin/python scripts/e2e_with_postgres.py --http-only --native-client
```

商品/小数清单/私图/登记/本人历史/取消/越权/询货调用经过真实API和PG。私图真实下载并核对JPEG字节。选择图片与压缩使用合成夹具，不是真实相机或微信压缩。
3. 微信工具/真机、WXML渲染、真实登录、分享/码、合法域名、权限拒绝、iOS/Android差异，均单独NOT_RUN/BLOCKED。不得将上述两类自动测试改写为真机通过。

本轮尝试读取微信官方wx.request/chooseMedia页面未成功（网页工具返回不可打开）；开发依据实际安装的miniprogram-api-typings5.2.3检查API形状。涉及wx.request redirect的类型说明要求基础库3.2.2；真实工具中须重新核验基础库版本与兼容性，不声称已在线核验所有官方行为。

## 草稿与中断

- 令牌只在内存；后台页面隐藏时清除私有列表/图片，身份切换拒绝陈旧响应。
- 业务写入前先保存载荷和幂等键。网络未知时锁定原内容，仅重试原请求。确认成功后先清草稿，再清待确认请求；进程在中间退出仍可以同键恢复。
- 已知校验失败允许修改；登录过期/超时/限流保留原请求。
- 当前仅合成资料。草稿存于当前小程序设备存储；正式隐私和保留政策发布前确认。退出不等于删除已提交需求。
- 图片选择/压缩/上传取消或失败不提交业务。上传失败结果未知时可能有仅本人可读的未关联文件，不能据此声称需求已收到；无自动删除真实文件的任务。
- 只有日期未填时刻时保留为日期备注，不伪造午夜时间；日期+时刻显式按北京时间转带时区字段。未确认候选不显示为已承诺交付。
