# 数据库与图片离线备份/恢复

状态：工具已实现，同一Dot云电脑的隔离合成数据库已做初次真实演练，最终被测SHA和结果见TESTING索引。本文件不授权连接或修改生产，不把开发演练当成生产恢复验收。

## 1. 适用范围与停止条件

- PostgreSQL 16，当前迁移0009；数据库与图片共同备份。
- 只处理可信、本项目自己生成的本地备份包。SHA-256检测损坏，不证明备份作者可信；pg_restore会执行归档中的SQL，绝不能恢复来历不明的包。
- 采取停写方式，不提供在线不停机备份一致性保证。必须停止API以及所有其他写入进程，确认没有上传、后台任务或人工SQL写入。
- --writers-stopped只是操作者确认，工具不能证明所有第三方写入者都已停止；前后表计数与图片清单检查也不能替代停写。
- 不直接恢复到原库、不覆盖非空数据库、不覆盖已有图片目录。没有DROP/--clean自动清库逻辑。
- 数据库和文件系统不是一个跨资源原子事务。恢复期间保持停服；任何异常保留新目标和备份，核对后决定如何重试，不自动删除或强行启动。
- 生产操作、备份保存地点/保留周期和访问权限需要另行批准。真实备份不进Git、Library、聊天附件或公开链接。

## 2. 准备

在仓库根目录，使用该版本依赖锁安装好的Python 3.12虚拟环境；可执行文件PG_BIN指向可信官方安装的PostgreSQL 16工具目录。包含pg_dump、pg_restore；跨PG主版本迁移本工具拒绝，必须另做迁移验证。

配置来源：环境变量优先，或当前目录受保护的.env，按数据读取而不执行shell。只需DATABASE_URL（postgresql+psycopg格式，显式主机、用户、数据库）与PG_BIN。密码不要贴聊天、命令参数或提交Git；使用服务器已批准的安全配置方式。数据库名称只接受普通标识符，避免CLI连接串歧义。

示意（不要复制空值直接执行）：

```dotenv
DATABASE_URL=
PG_BIN=/usr/lib/postgresql/16/bin
```

- 预先准备备份父目录、独立的新空数据库和目标目录的父目录；磁盘空间同时满足归档、源数据、新库与图片副本。
- 目标数据库/角色创建、系统权限配置不是本工具自动完成的步骤。生产需操作者确认目标，数据库用户应只有必要权限，不为便利使用长期超级用户。
- 保存对应源码/制品SHA、依赖锁与配置版本。包会记录可读到的Git SHA/dirty；源码制品没有.git时字段为空，必须另外保存release标识。备份不包含.env、AppSecret或签名密钥，凭据单独按已批准渠道管理。
- PostgreSQL子命令最多600秒；失败后保持停服，包/新目标可能不完整。较大数据量需另评估方案，不默认提高限制或切换外部服务。

## 3. 备份

确认停写后执行；输出bundle路径必须尚不存在，父目录须已存在：

```bash
export PYTHONPATH="$PWD/apps/api"
.venv/bin/python -m local_shop.recovery backup \
  --bundle /approved-backup-location/local-shop-YYYYMMDDTHHMMSSZ \
  --media-root /approved-local-shop-media-path \
  --writers-stopped
```

这里路径都是待替换的占位，不是本次已存在的生产路径。没有图片时也应有专用空media目录。

成功包结构：

```text
manifest.json       格式、UTC时间、PG工具/服务器版本、代码版本、迁移、表计数、哈希清单
database.dump       PostgreSQL custom格式归档
media/*.jpg         本项目生成的规范UUID文件名；含公开、私有和归档图片
```

工具以新目录、私有权限、独占文件创建写入；清理继承的PGSERVICE/PGHOST等，连接凭据经子进程环境传递，不放命令参数。图片逐字节哈希与数据库storage_key/size/sha256比对。缺少数据库引用的图片会失败；不把“只备份到了数据库”报告为完整备份。

失败输出目录保留；缺少manifest或校验失败的包不能使用。不要覆盖失败目录重新跑，应调查原因并选择新的输出目录。

## 4. 离线校验

```bash
PYTHONPATH=apps/api .venv/bin/python -m local_shop.recovery verify \
  --bundle /approved-backup-location/local-shop-YYYYMMDDTHHMMSSZ
```

校验不连接数据库，检查归档/媒体哈希、清单和文件名，拒绝符号链接、缺失/额外文件。成功不等于数据库可恢复，更不等于备份来源可信；仍需恢复演练。

## 5. 恢复到独立空目标

1. 保留原库、原media和原制品，不删除。
2. 由获授权操作者建立独立空数据库，不能已有应用表、序列、视图、函数、自定义类型/schema或额外扩展。
3. 将本次恢复进程的DATABASE_URL切到新目标，核对主机/端口/数据库名；不要仅修改命令显示标签。
4. 指定尚不存在的新图片目录。服务保持停止。
5. 运行：

```bash
PYTHONPATH=apps/api .venv/bin/python -m local_shop.recovery restore \
  --bundle /approved-backup-location/local-shop-YYYYMMDDTHHMMSSZ \
  --media-root /approved-new-media-parent/local-shop-restored-media \
  --empty-target-confirmed
```

恢复先校验包并检查目标，再独占创建新图片目录、校验复制文件，通过pg_restore单事务恢复新库。成功后再次比较迁移、所有public表计数和数据库媒体清单。不恢复原数据库角色/密码/ACL，也不授予新的平台角色。

任一步失败：保持目标离线。新图片目录可能已存在、数据库可能尚未恢复或已恢复待核查；工具不会为重试自动删除它们。检查结果后选择另一个经过批准的新空目标，或按故障性质执行人工恢复。数据库与图片切换必须一起完成，不可把旧库指向新目录混用。

## 6. 验收与切换

至少在目标上验证：
- 健康检查、迁移版本、各表计数；不是只有数据库进程启动。
- 原始需求/确认修订/状态事件/取消决定/平台操作审计都在。
- 原请求幂等键重放结果一致，不重复创建。
- 公开图片字节匹配；私有图仍需正确身份，其他顾客/商户越权失败。
- 店铺启停与成员归属正确；恢复不会将平台管理员变成所有店铺成员。

先隔离验证，再由用户决定是否切换生产配置/入口。当前项目真实微信认证、隐私与浏览器/真机验收仍缺失，不能因为本恢复工具通过而上线。

恢复数据与旧代码未必兼容。回滚应选择明确代码SHA与对应DB/media恢复点；不能盲目alembic downgrade，尤其0009在已有邀请/审计历史时会主动拒绝降级。切回前同样停写、备份当前状态并明确可能丢失恢复点后的新数据，经用户批准。

## 7. 本机合成演练

```bash
PG_BIN=/path/to/trusted/postgresql-16/bin \
  .venv/bin/python scripts/backup_restore_drill.py
```

脚本只创建临时PG集群和合成资料，不接受现有数据库地址或用户数据目录。它真实跑店铺/代记/询货/取消/修订/公私图/平台流程，停止唯一API写入者，pg_dump与图片备份，恢复到另一空库，重启PG/API后验证HTTP结果；还验证损坏包、缺图片、非空/原库/已有目录拒绝。临时dump和图片退出即清理，不上传。

这些结果仅覆盖同一Dot云电脑、PG16.15和合成数据；目标Linux服务器、真正异机灾备、保留周期、RPO/RTO和真实容量仍待批准后验证。

## 只读候选检查

scripts/maintenance_check.py使用只读数据库事务，报告过期/撤销会话、过期工作台确认和媒体未引用候选；不提供删除参数。文件刚上传尚未提交、历史关联、备份和保留政策必须人工核对。真实客户数据和备份不自动上传/删除。正式身份映射和会话摘要也属于数据库备份范围；恢复时若更换APP_SECRET_KEY或AppID，旧会话失效，需要重新登录，不能以开发账号代替。
