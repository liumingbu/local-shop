# 安全、租户与隐私约束

本文件是产品/工程要求，不替代正式合规审查。

## 1. 公开与私有字段

公开：商家已审核发布的店名、Logo、商品、营业时间、经营联系电话/地址（商家明确选择公开）。

私有：顾客电话、配送地址、原始咨询私图、商户内部备注、成员账号、入驻证件、平台运维信息。公开API不得因复用ORM模型把这些字段带出。

商品图片可公开；咨询、入驻证明不能与商品图共享无鉴权静态路径。

## 2. 权限

每次私有读取/修改校验主体身份、租户成员角色和资源归属，父子关联同租户。列表、单条详情、附件下载、统计、导出（如实现）都要测试，不能仅测试单个API。

顾客只能读本人记录。老板代录未知顾客的记录没有自动顾客归属；同名、同电话不充分。绝不创建“输入手机号就能查订单”的公开接口。

平台运维跨租户能力最小化、显式权限、审计。商户暂停后关闭对应新增公开操作，但保留依法和产品约定的必要历史处理通道，具体政策发布前确认。

## 3. 开发与生产

演示用户、假微信code和测试签名仅在受控开发环境使用。生产缺少真实配置或开启开发身份时拒绝启动；不得静默降级为模拟登录。

不提交.env、令牌、AppSecret、SSH密钥、p12证书、数据库备份。示例只使用空值/占位，合成数据无真实电话地址。

错误日志脱敏，避免记录完整请求体、凭据、图片下载签名或客户隐私。

## 4. 上传

验证图片格式和实际解码，限制大小/数量，随机安全storage_key，防路径穿越和跨租户media_id引用。EXIF可能含位置，外发公开图须按方案清理。首版不支持可执行格式或任意远程URL抓取。

## 5. 操作安全

需求创建限流、幂等；状态变更版本控制、事件留痕。管理端输入和富文本按纯文本/允许清单呈现，避免脚本执行。CORS、会话/CSRF方案和密码存储（如有）在实施时采用明确安全配置并测试。

## 6. 隐私和数据生命周期

只收完成当前操作所需信息；浏览不强制交手机号。真实接入前提供隐私告知、所需授权、删除/更正渠道、保留和备份策略，由用户确认。

入驻商家资质由实际品类决定，平台不能放任冒用店名或虚假资质。业务内容和审核材料一致，不靠隐藏功能过审。

## 7. 上线阻塞的安全项

跨租户泄露、顾客记录越权、生产假登录、明文敏感信息、私有图可公开访问、状态机可被客户端任意改写，都必须作为阻止试用发布的问题，不得仅记录成可忽略风险。

## 已实现的私图边界（2026-10-13 M4b）

上传者私图在提交前仅本人可读；提交后本店商户通过记录关联可读。顾客本人接口不输出商户内部新增图片。公私用途不可由PATCH更换，商品/Logo引用必须匹配对应公开用途。
图片持久目录不作为静态目录暴露；所有私图请求仍鉴权，图片URL本身不是凭据。真实性来自PG/HTTP/文件测试，尚未证明微信真机上传或正式隐私授权可用。
