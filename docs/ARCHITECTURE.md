# 架构建议｜模块化单体、单仓库、多租户

状态：建议技术基线；不是已部署架构。用户发送长期任务视作允许按基线实施，实际版本仍须验证并锁定。

## 1. 组件

| 部分 | 默认选择 | 用途 |
|---|---|---|
| 顾客/商户小程序 | 微信原生 + TypeScript | 最终手机主入口 |
| 管理 Web | Vue 3 + TypeScript + Vite | 早期可测工作台、批量维护、平台管理 |
| API | Python 3.12 + FastAPI | 模块化单体业务与鉴权 |
| 数据访问 | SQLAlchemy + Alembic | 类型、事务、可重复迁移 |
| 数据库 | PostgreSQL，建议16系列受支持补丁版 | 多租户约束、事务、持久化；实施时核验支持状态 |
| Node | 实施时受支持的 LTS | 锁定真实版本，不用 latest 漂移 |
| 测试 | pytest；前端单元测试及浏览器测试按需 | 所有执行默认位于 Dot 云电脑 |
| 交付 | 单台 Linux + 反向代理；Compose 可选 | 不预购资源，不把开发电脑作为生产服务 |

选型是本项目方案，不需要假设用户已经安装上述工具。缺少工具先按 ENVIRONMENT_CHECK 验证。

## 3. 后端模块边界

`identity` 身份与会话；`tenants` 租户与成员；`stores` 公开门店；`catalog` 商品分类图片；`inquiries` 咨询；`reservations` 需求、代记、状态与交付；`media` 文件；`platform` 审核与冻结；`audit` 审计。

API路由负责请求/响应校验；服务层控制权限、状态和事务；数据访问层在上下文中强制租户范围。业务代码不能随便暴露“按ID查任意对象”的公共工具。

## 4. 身份模型

平台主体用户 `users` 与租户成员 `tenant_members` 分开。未来微信身份以应用范围内服务端验证的身份标识关联用户，不接受前端自报 openid。

开发专用身份模拟器只为合成用户服务，默认关闭、不得远程公开，生产配置即使被误打开也要拒绝启动。真实微信未接入前的结果明确标记开发身份模拟。

老板代记中的自由顾客信息不是用户账号；`customer_user_id` 可以为空。不按未核实电话自动回填。将来认领需专门的身份核验方案，首版不做自动认领。

## 5. 多租户

公开定位参数指定访问的店铺，身份权限由服务端决定。所有私有业务表有 `tenant_id`，关联对象必须属于同租户。服务层过滤、数据库复合约束及越权测试同时保护，不以“用了UUID”代替权限。

平台管理员入口与商户入口分开；跨租户运维操作必须显式权限和审计。不得为了调试给所有账号平台管理员权限。

## 6. 文件

开发阶段使用本机受控目录，生产目标可先使用同机持久卷并提供存储适配层。商品公开图与咨询私有图分开，不能把全部 uploads 目录暴露为无鉴权静态站点。

图片限制大小、类型、数量，生成安全文件名，进行实际解码校验，保留业务归属。SVG/HTML不作为首版可上传图片类型。缩略图压缩可做基础能力，不强制外部对象存储。

## 7. 微信接入边界

网络客户端独立封装，可以在开发配置中指向测试API，正式域名、登录凭据、分享二维码和订阅提醒需真实条件验证。AnyService 不作为默认依赖，本项目不假定旧项目环境可用。

前端接口、模拟场景和生产适配器分离。正式小程序网络/静态图片、iOS/Android真机、隐私授权、分享入口均是独立验收，不能被浏览器演示替代。

## 8. 不确定环境的处理

Docker缺失时，可在 Dot 云电脑内用 Python虚拟环境/Node进程及本机可用PostgreSQL开发；没有真实PostgreSQL就先做不依赖DB的单元测试，将数据库集成标记阻塞。不得自动换SQLite作为正式架构，不切换外部云服务规避限制。

没有官方开发者工具/真机时，完成能真实运行的静态、单元和接口测试，记录微信端未测。提出最小人工验收步骤，不强行声称全部完成。

## 9. 配置与可复现

实现后至少包含：明确运行时版本、实际依赖锁、`.env.example`配置契约、迁移顺序、合成数据初始化、工作目录、启动和测试命令。环境信息进入报告，但凭据/私有网络细节不进公共日志。

不提前启用自动CI。GitHub Actions可以后续经授权增加，但不能当作 Dot 云电脑验证的替代品。
